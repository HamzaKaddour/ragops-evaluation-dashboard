Methodology

How the evaluation artifacts are produced

Corpus · Queries · Metrics

1. Labeled evaluation set

The pipeline starts from a compact document corpus and labeled evaluation queries. Each query lists the source documents that should be retrieved and the answer topics expected in a supported response.

2. Retrieval variants

Four retrieval configurations are compared: keyword retrieval, dense-style semantic retrieval, hybrid score fusion, and hybrid retrieval with relevance-aware reranking.

3. Ranking metrics

The script computes Recall@5, Precision@5, MRR, and nDCG@5 from the retrieved documents and the labeled relevant document set.

4. Reliability scores

Groundedness, citation coverage, and hallucination risk are estimated from retrieval coverage and precision, then attached to each query-level trace.

5. Operational trade-offs

Each pipeline variant includes latency and cost estimates so quality can be compared against serving constraints.

6. Trace inspection

Each evaluated query stores retrieved source snippets, ranking scores, generated answer text, metrics, and failure tags for debugging.

Evaluation workflow

How the reliability checks are organized

Retrieval diagnostics

Each pipeline is scored using ranking metrics such as Recall@K, Precision@K, MRR, and nDCG to expose retrieval gaps before answer generation.

Grounding analysis

Generated answers are evaluated against retrieved evidence to estimate citation coverage, unsupported-claim risk, and overall faithfulness.

Operational monitoring

Latency, estimated token cost, and failure categories are tracked per pipeline to support practical deployment decisions.
