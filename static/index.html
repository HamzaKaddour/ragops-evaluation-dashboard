First, the idea

What is RAG?

Retrieval-Augmented Generation (RAG) is a way to give a language model relevant information at question time. Instead of relying only on what the model learned during training, the system first searches a document collection and then gives the best matching passages to the model as context.

In practical terms: search first, answer second. That makes it possible to use private or frequently changing information without retraining the model.

Simple example

A user asks:

“Which metrics should I use to evaluate retrieval quality?”

The system searches the local corpus, retrieves passages about Recall@K, MRR and nDCG, reranks them, and asks the local model to answer only from that evidence.

What this project adds around a basic RAG pipeline

Hybrid retrieval

BM25 handles exact terms while dense embeddings capture semantic similarity. Their scores are fused before reranking.

Evidence checks

A CrossEncoder confidence gate can stop generation when retrieved evidence is too weak, rather than asking the model to guess.

Evaluation and traces

Each run records retrieval quality, groundedness, citations, abstention behavior, and latency so failures can be diagnosed.

What happens when a question is submitted

The stages below are executed locally when the FastAPI backend is running.

1

Search

BM25 and dense vector retrieval each find candidate passages.

2

Fuse

Lexical and semantic retrieval scores are normalized and combined.

3

Rerank

A CrossEncoder scores query–passage pairs more precisely.

4

Check evidence

Weak retrieval can trigger an abstention before generation.

5

Generate

Qwen answers from the retrieved context using local inference.

6

Verify & log

Citations, groundedness, latency and sources are evaluated and stored.

What do “groundedness,” “citation validity,” and “citation coverage” mean?

Groundedness estimates whether answer sentences are semantically supported by retrieved passages. Citation validity checks whether cited source IDs actually belong to the retrieved set. Citation coverage measures how many factual answer sentences include a source citation.

Why does the system sometimes refuse to answer?

If the strongest reranked passage falls below a calibrated confidence threshold, generation is skipped and the system returns an insufficient-evidence response. This is intended to reduce unsupported answers when retrieval is weak.

Why is this public page read-only?

GitHub Pages serves static files only. The full FastAPI, FAISS, CrossEncoder and Qwen pipeline runs locally on the workstation. This page publishes recorded benchmark artifacts so the project can be inspected without keeping a GPU machine online.
